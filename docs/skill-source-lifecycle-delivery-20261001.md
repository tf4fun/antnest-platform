# Skill 来源生命周期：DI2 集成验收

2026-10-01：DI2 已通过正常 Agent 停用、启用和删除的完整 Docker 集成验收。
本批只修改共享语义说明、根 tests 和交付文档，没有修改服务业务实现。
它补充[四步技术方案](evolver-technical-analysis.md#117-所有权批次与完成标准)
要求的真实来源不可用与删除场景；此前
[DI1](skill-propagation-integration-delivery-20261001.md)覆盖的目录内容变化失效
仍保留独立证据，没有把模拟来源删除视为正常 Controller Delete。

## 检查的业务边界

使用[普通部署配置](skill-deployment.md)和正常 Identity/Gateway 会话，先完成
真实学习生成/更新、双 Agent 检索和临时文件使用、浏览器显式提升 v1/v2、
模板冻结及两 Agent 重建。随后通过 Console BFF 调用 Controller 的既有
Disable、Enable 和 Delete，不直接改任何服务数据库或来源映射。

| 来源操作 | 要求与核验                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Disable  | 所有者访问及受管内容身份保留，Runtime 被移除、工作区卷保留；来源搜索/读取返回 503 source_unavailable，禁止历史候选兜底；正式 v1/v2 与另一个 Agent 的预设仍可读取和执行 |
| Enable   | 新 Runtime 保留原工作区，重新核验完整来源清单；未变的来源仍为原序号及摘要，恢复读取，不重新运行学习模型                                                                |
| Delete   | 正常删除来源 Runtime 和工作区；旧来源引用返回 404 not_found，目录不再展示；后台送达递增失效墓碑；正式版本和已分发预设保持独立                                          |

规则见[来源合同](../contracts/skill-registry/discovery-api.md)。首版来源仍按
所有者授权，未增加组织范围共享。失效墓碑由现有持久工作器补送；可见性和
读取权限立即使用 Controller 已发布的当前配置，不等待目录完成补送。
