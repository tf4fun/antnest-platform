# Skill 动态发现：Console D6 来源展示与用户提升

日期：2026-10-01。本批属于 Admin Console，消费已交付的 Registry 发现/提升
接口。所属单元、合同、HTTP 组件、生产构建、浏览器与隔离 Docker 门禁通过。
完整四步传播另由 [DI1](skill-propagation-integration-delivery-20261001.md) 通过
真实来源、登录、临时使用、模板及重建/Run 集成，本批保持 Console 所属证据范围。

## 已交付行为

- 按[Console 合同](../contracts/admin-console/skill-discovery.md)先补测试，再实现
  搜索、预览和提升三个 BFF 接口。组织与操作人来自已认证 principal，沿用现有
  管理员发布权限；动态来源仍只限调用者拥有的 Agent。管理员角色本身不赋予
  读取他人个人 Skill 的权限。
- Skills 页增加 **Discover Agent Skills**。搜索返回当前来源身份、名称、描述与
  摘要；用户点击后按需读取完整来源包，查看 SKILL.md、文件清单、源 Agent、
  变更序号和摘要，再明确确认提升。正文以文本展示。
- 预览不写入 Runtime 或正式 Registry 版本。BFF 最多接收 8 MiB ZIP，流式校验
  文件校验和与规范内容摘要；限制 256 项、32 MiB 解包总量及 16 KiB SKILL.md。
  仅正文和文件元数据进入响应，包不被长期保留。预览/提升共享现有两个包处理位。
- 提升支持新建正式 Skill，或明确选择同名正式 Skill 与当前版本进行追加。
  目标选择固定 expected_version，失败不会替用户换成新 head。内容、名称、
  版本或请求冲突要求重新审阅；传输错误与可重试故障保留原命令 key。
- 正式提交成功后刷新列表，刷新失败不会再次发布。结果提示引导选择固定
  Template 版本与显式 rebuild。来源个人包继续由 Agent 管理，正式版本由
  Registry 独立托管，后续来源变化不改变已发布内容。
- 真实 Docker 浏览器复核发现原有末页语义不匹配：Registry 使用空字符串/0，
  浏览器 DTO 使用 null。新增失败测试后在 BFF 统一转换，恢复末页的当前版本
  识别与新版本入口，并消除空的下一页按钮。

HTTP 测试桩，Gateway session/account 外壳由浏览器夹具提供。来源搜索、包读取、

真实自动学习、ACP 临时使用、登录、Template/RC/rebuild 的组合属于 DI1。

实际发布两个不同摘要的不可变版本。来源变化后的首次手机提交被拒，用户重新
审阅后才发布 v2；来源停用/不可用后，相同提交仍重放 v2 且不再读取来源，正式
v2 的下载字节保持一致。跨用户、跨组织、普通成员、伪造浏览器身份字段、
旧来源和旧正式 head 分别得到约定的拒绝。
