# Skill 前景搜索：D3A ACP 调用方派生

2026-10-01：本批只修改 Agent ACP Service 的搜索端口、HTTP 适配器、工具
分派及所属测试，承接 [D1A Registry](skill-discovery-caller-registry-delivery-20261001.md)。
所属功能门禁已通过，仍需 DI3 的真实活动 Run 集成；本批不单独证明完整前景修复。

## 行为与边界

`find_skill` 的内部请求增加 `requesting_agent_id`，值取自现有
`PostgresSkillDiscoveryAuthority` 对持久活动 Run/Session 的授权结果。
它与组织和所有者一起发送给 Registry，不取自模型参数或快照中的假定字段。
搜索端口要求此可信上下文，模型的严格输入合同保持不含该字段；即使模型
提供正确的调用方 ID，也在授权与网络 I/O 之前拒绝。

Registry 据此在候选上限和来源核验之前排除自己的个人投影，避免活动 Run
尝试取得自身的空闲维护执行位。正式版本和其他授权 Agent 来源继续参与
搜索，本地 Skill 继续通过普通 Runtime read 使用。`load_skill` 仍绑定选择
的引用、摘要和组织/所有者，不增加调用方过滤字段。用户界面预览与提升
不携带活动 Run 上下文，继续可以操作自己的来源。

调用前后重复授权、搜索/加载持久预算、取消与超时、错误净化、临时包交付
及回收均沿用现有实现。新增测试确认搜索期间持久调用方改变时丢弃候选，
不会把结果交给另一个执行身份。本批没有新增 Runtime 接口、表或后台监听。

| 静态检查            | 服务与根集成源码 lint、typecheck 通过                                   |

PostgreSQL 门禁约 227 秒完成，依赖项目按工具的清理记录完整移除。
原有 17 个停止容器、0 个运行容器、15 个网络、11 个卷保持相同。

单元新断言先在未下发调用方字段时失败，随后实现通过。全量单元的首次运行
因沙箱拒绝回环监听出现 `EPERM`；允许本机监听后通过。根集成 lint 发现
两处既有测试桩的 `async` 没有 `await`，已改为显式返回 Promise，并通过
真实 SDK 集成回归。新测试误用快照字段的类型错误也已纠正。失败证据均保留。

私有证据位于 `artifacts/verification/skill-discovery-caller-d3a-20261001/`；
最终门禁索引为 `admission.json`。没有使用付费模型、实际部署凭据或缓存
测试源。本批不启动原有停止的 Docker 验收环境。
