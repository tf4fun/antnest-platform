## 核验边界与后续门禁

本轮复核本地 schema、Controller/RC/Runtime/ACP 实现与现有恢复资产；包括本机
`yaml-rust2 0.13` 与本机 go-yaml v3 的实际类型推断源码；复审补充核对了 RC
prepareOperation、Controller 重建/Enable 和 Console 审计投影。YAML 基础规则
另对照 [YAML 1.2 core](https://yaml.org/spec/1.2.2/#1032-tag-resolution)。此前查阅了
[Linux rename 系统调用手册](https://man7.org/linux/man-pages/man2/rename.2.html)，
只用于确认目录交换/不覆盖语义，不能据此证明部署卷支持。此前 Hermes/Evolver
调研快照继续保留，未重新运行上游项目。

第三轮再核对本机 YAML 的前缀剥离/有符号整数解析和 Go 的 merge 分支，以及
Runtime 的环境变量 bootstrap、Docker 创建/接管/启动和部署摘要、RC 请求重放
与破坏性失败语义。另查阅 [Docker 卷文档](https://docs.docker.com/engine/storage/volumes/)
确认缺失 named volume 的自动创建行为；未以 Docker 实验验证竞态或清理实现。

以下均为**待验证**，不能以文档修订标记通过：

- 停止的 Docker 准备容器是否能通过 archive API 正确写入 named volume。
- Docker/Desktop 上的完整目录交换、持久化与中断恢复能力。
- 真实 Go/Rust 校验的一致性、最大包/集合的准备预算和逐包续作。
- 持久引用跨 Drain/Fence、Fence 后恢复源及 Enable 网络前检查。
- 容器创建前检查后的删卷竞态、启动门禁和重放接管，清理不误删外部资源。
- 前景/复盘/Drain 竞争、受管静止分类、显式用户发起/确认及后置内容核验。
- 独立维护端点的 Runtime 拒绝与凭据边界、Console 审计正文删除。
- 公钥轮换/泄露隔离、冻结部署身份及旧备份恢复；包规则/提示版本追溯。
- 候选等待期间普通 Run 可停止后台任务，实际退出后重新核验并恢复应用。

Controller 的说明、阶段四/当前状态/服务所有权、合同索引、产品范围及备份文档
同步标注为未来要求；现有七数据库恢复证据和阶段三验收状态未改写。本轮不运行
业务测试、构建或 Docker，不修改运行环境，也不代替 B0/L0 的正式合同交付。
