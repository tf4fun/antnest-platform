## 1. 产品目标与本次修订

自动积累可复用经验应是正常使用 Agent 的结果。用户不必先发现经验值得保存，
再逐次发起整理、审核候选。建议首版主流程改为：**任务结束 → 有条件后台复盘 →
生成或更新受管个人 Skill → 自动检查 → 空闲激活 → 后续 Run 按需使用**。
用户主动保存是补充入口。研究阶段曾建议提供查看、撤销和固定等控制手段；
当前首版只保留已纳入 L0 合同的能力。
完成后的提醒采用 [SDK notice 方案](skill-learning-notifications-design.md)：ACP
保存学习结果并发送 SDK notice，Node Bridge 经现有 SSE 呈现；Server、Bridge
和 FE 分别负责持久发布、补读及去重恢复，不把通知当作新的模型回答。

这替代 2026-09-27 草案中“先做人工确认闭环、后台只提候选、自动应用另立项”的
产品选择。已评审的系统只读、服务所有权、真实目录、前景优先和内容冲突处理仍
适用。本文不把这一方向变化记作功能已经交付，也不重新打开旧资产迁移范围。

## 3. Hermes 实际做了什么

### 3.1 自动触发与直接写入

结束阶段检查 Skill 迭代阈值、`skill_manage` 可用性、最终回复、未中断及
`skip_background_review` 等条件，再发起后台复盘。这个条件不是业务成功证明：
触发分支并没有直接要求 `completed=true`。后台开关在配置未指定时默认为开启；
自动路径不需要用户点击。复盘可以直接调用受限 Skill 管理工具写入，之后从
实际工具结果形成通知，不经过逐次候选审批。见上表前两个文件。

### 3.2 维护范围与更新优先级

复盘优先扩充已使用的受管 Skill，再查已有主题，最后才新建可复用的主题。
其写入保护检查归属、固定状态和来源，自动维护不能因为“本轮读过”就接管
用户手写、安装或外部提供的包；现有文件需要在本次复盘重新读取。提示还要求
提炼步骤而非会话流水账。见
[更新提示](https://github.com/NousResearch/hermes-agent/blob/1b91b8eaa576b3c3dfe08e4592bdd698d1aca019/agent/background_review.py#L417-L498)
及上表的写入保护。提示中的语义要求不等于程序能证明提炼正确。

### 3.3 前景优先、成本与另一条整理流程

Hermes 用独立复盘实例及派发白名单限制工具；新前景会取消旧复盘，等待有上限，
超时后仍继续前景。复盘有调用/输入预算，费用归到父会话。相同模型可复用提示
前缀，切换模型时使用压缩历史。见
[取消及预算](https://github.com/NousResearch/hermes-agent/blob/1b91b8eaa576b3c3dfe08e4592bdd698d1aca019/agent/background_review.py#L120-L220)
和 [受限派发](https://github.com/NousResearch/hermes-agent/blob/1b91b8eaa576b3c3dfe08e4592bdd698d1aca019/agent/background_review.py#L1085-L1195)。

Curator 是独立的空闲期整理流程：状态老化/归档与模型合并分开，后者
`DEFAULT_CONSOLIDATE=False`。不能用“模型合并默认关闭”推导出普通自动生成也
关闭。首版采用任务后的学习，不同时引入整库合并、自动归档和淘汰。见上表
`curator.py`，其时间参数仅是上游事实，不直接作为平台配置默认值。

## 4. 平台采用与调整

下面是针对本平台的设计建议，不是 Hermes 的现成功能。

| 决策 | 本平台拟采用的行为 |
| --- | --- |
| 正常入口 | 默认自动学习；基于已持久化的真实 Run 及有效 Agent 策略发起，浏览器离线也能运行 |
| 应用方式 | 满足受管范围和检查条件的候选自动激活，记录策略修订与精确内容摘要，不逐次索要确认 |
| 维护归属 | 自动新建的个人 Skill 由 ACP 登记受管身份；既有用户包需显式纳入，固定或手工修改后暂停自动维护 |
| 更新选择 | 优先相关且受管的已有主题；系统包仅用于参考及判重，不能覆盖或用同名个人包遮蔽 |
| 内容形态 | 流程、步骤、实际有效的修复和适用条件；无新经验可以跳过，不设每轮产出指标 |
| 控制通道 | 沿用已评审的 ACP 内部任务与 Runtime 私有维护端点，不把维护提交能力注册为前景模型工具 |
| 并发 | 全局一个复盘、每 Agent 一个；模型调用不持有 Runtime，前景到来取消复盘，短文件副作用先结算 |
| 可见性 | 成功后轻量显示已新增/已更新，提供差异、来源、撤销和固定；跳过和普通暂缓不弹审批框 |
| 发布 | 学到的经验留在本 Agent 的个人目录；组织共享仍走管理员上传、Template 修订与显式重建 |

### 4.1 为什么不直接移植整个 fork

[当前 RunSupervisor](../services/agent-acp-service/src/application/run-supervisor.ts)
限制每 Agent 一个活动 Run；[Runtime 合同](../runtimes/antnest-runtime/docs/mcp-contract.md)
让 Tool 和 info 读取共用一个执行槽。后台照搬普通 Run 会使用户遇到
`agent_busy`；绕过准入直接读文件又会撞上 `runtime_busy`。

| 复盘执行方式 | 取舍 |
| --- | --- |
| 前景 Run 结束前顺带写 Skill | 容易复用当前工具，但延迟用户拿到最终结果，也延长 Drain；不作为自动主路径 |
| 完整复制 Hermes 式后台 Agent 工具循环 | 模型可以多轮搜索与修改；须另外解决 Runtime 槽、工具隔离、上下文和费用上限，不能直接移植 Python fork |
| ACP 独立有界任务，模型提炼、程序读写 | 首版建议；复用现有客户端及固定来源，易约束预算和副作用；复杂任务若资料不足会跳过，后续可在同一权限边界扩展受限读取轮次 |

拟由 ACP 的现有 worker 执行独立、有界维护任务，使用现有模型客户端；维护模型
只输出结构化的目标/变更/来源，由程序验证后经私有端点准备和提交。模型上下文
只包含本次证据和有限相关 Skill，不复制前景完整工具目录或假造用户 Run。
若两次受限生成都没有合格结果，就跳过或记录原因，不运行自由工具循环自测。

模型推理可立即失效，迟到响应不能产生写入；已经发送的文件操作必须观察到
结束或按摘要恢复后才开始前景 info。这是本平台单槽设计需要保留的适配，不能
承诺任何异常下都零等待，也不能照搬“超时后无条件放行”。

### 4.2 自动生效不意味着接管所有个人文件

默认策略允许自动创建，以及更新 ACP 已登记的自动生成 Skill；归属来自控制
记录，不相信目录名、frontmatter 或模型自报。用户定向创建的个人包默认仍由
用户维护。读取时发现内容与上次受管摘要不同、目录被改名/移动或出现系统同名
包，就暂停该路径的自动写入，保留现有文件。这只在正常维护和提交时核对，
不持续监听工作区或逐 Run 扫描所有包。

对有效范围内的自动候选，ACP 持久化 `apply_basis=policy`、策略修订及摘要，
无需伪造用户确认。人工采纳例外候选时使用 `apply_basis=user_action`，绑定
真实用户操作及确切目标内容。低可信资料不能单独支撑自动规则；来源关联和
摘要检查可以程序化，语义正确性仍有模型误判可能，自动生成只代表检查及策略
通过，不能标注成“业务验证通过”。用户确认也不替代测试。

已应用更新保留有界旧副本。撤销只在活动内容仍匹配本次更新时恢复；首次创建
则移出发现目录并保留恢复副本。撤销同时暂停该主题自动维护，避免下一次又写回。
发生并发人工编辑时停止并显示冲突，不强行覆盖。

### 4.3 最小触发与成本建议

ACP 从已持久化的 `completed` Run 取得证据，普通问答/状态查询优先跳过；真实
用户纠正、使用受管 Skill 后的修复、达到阈值的工具迭代可进入复盘。纠正线索只
决定是否值得复盘，不改变调用权限。首版不从 failed/cancelled/unresolved Run
自动写“成功流程”，学习任务也不再次触发学习。

建议初值如下，均是待 L0 固定的产品/运行参数，不声称有实测依据：

| 参数 | 建议初值及理由 |
| --- | --- |
| 开关 | 新 Agent 默认 `automatic`，可设为 `off`；关闭停止后台触发，仍可使用已有 Skill |
| 粗筛 | 完成 Run 中至少 3 个含工具调用的模型轮次，或有真实用户纠正线索/已用 Skill 的纠错线索；并非每 3 次强制写入 |
| 调度 | 同 Agent 10 分钟冷却、空闲 15 秒后尝试；待处理来源合并，排队不计运行失败 |
| 单次生成 | 最多 2 次模型调用（含一次格式修正）；累计输入 16k token、累计输出 4k token、90 秒；每次最多更新/新建 1 个 Skill |
| 日上限 | 每 Agent 最多 20 次复盘尝试，并服从更低的 owner/组织额度；预占预算，取消也记录已发生用量 |
| 内容 | 完整 SKILL.md 和包限制沿用 Registry；证据不足或超过模型输入预算时跳过，不能静默截断重要约束 |
| 保留 | 每主题最多 5 个可回退版本；候选/旧副本总预算建议每 Agent 256 MiB，不能清掉在途恢复需要的目录 |

计数使用 ACP 真实模型/工具记录；冷却不能让新证据无限覆盖旧任务而永远不处理。
持久任务按组织、Agent、来源 Run 和自动触发类型去重；重试不因提示/配置版本
变化而新建同源任务或重置预算，实际重试的模型调用仍计入用量。Run 成功持久化与回复不依赖后台入队
成功，worker 可以有界补扫终态记录，恢复扫描范围在 L0 明确。

## 5. 固定方案前要验证的事项

1. 选择代表性样例核对粗筛：普通对话跳过，真实纠正及有效修复有机会学习；不把
   工具文本中的“用户要求”视作用户证据。先固定样例和预期，再进入实现测试。
2. 核对默认预算与当前模型窗口/输出上限，定义来源过长的选择规则、补扫范围和
   待处理来源/候选总量；上表参数不以 Hermes 的较大预算直接替代。
3. 沿用已评审的真实卷目录交换及后台任务观察要求，列出 Runtime 单槽下的取消、
   崩溃恢复和正常 Run 抢占门禁；是否达标以后由 Docker 实测证明。
4. 固定事后撤销、手工修改后暂停、关闭学习及重建同名冲突的状态和界面语义。
   学习质量样例需评估重复、过度泛化、错误负面规则，不能以生成数量作为成功率。

按 L0 → Runtime L1 → RC L1R → Controller L2 → ACP L3 → UI L4 → LI1 推进；
**L3/LI1 必须包含自动触发、自动应用和前景竞争**。人工入口作为 L5a/L5b/LI2 的补充
交付，不能再成为自动学习上线的前置条件。批次仅是待冻结计划，本轮未启动。
