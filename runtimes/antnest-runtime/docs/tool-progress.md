# Tool Progress

## Scope And Contract

F02 is delivered in two service batches. This Runtime producer batch adds live
progress for built-in Bash and managed stdio MCP calls. ACP consumption and
`tool_call_update` persistence/presentation remain a subsequent batch. It does
not add Runtime tables, durable queues, a new endpoint, or per-packet telemetry.

The caller supplies `_meta.progressToken` in `tools/call`. Runtime uses the
official SDK's `notifications/progress` on that request's Streamable HTTP
response. Without a token there are no progress notifications. Tokens belong
to the caller and active request only, not an Agent or a durable subscription.
See the [MCP progress contract](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/progress)
and the pinned `rmcp` model used by Runtime's `2026-07-28` transport.

1. Bash reports captured stdout/stderr increments as human-readable messages
   prefixed `stdout: ` or `stderr: `. `progress` counts emitted preview UTF-8 bytes;
   `total` is absent. It is not a percentage or a heartbeat. Per-stream byte
   order is preserved; no causal ordering between the two OS pipes is claimed.
2. UTF-8 sequences split across reads are retained until complete. Invalid
   bytes use replacement characters, consistently with the final Bash result.
   Final stdout/stderr remain authoritative and retain their 1 MiB per-stream
   bound. A silent command produces no invented progress.
3. Managed MCP progress is observed at the SDK-decoded transport boundary,
   before dispatch can return a result. Subscribe before sending the child
   request; filter on its SDK-generated token, then rewrite only the token to
   the outer caller's token. Preserve valid increasing progress/optional total
   and bounded message text. Ignore unrelated, late or non-increasing reports.
4. Progress is an optional, bounded live preview, not a reliable event journal.
   Each request has at most 32 queued reports, 8 KiB message text per report,
   and 256 forwarded reports. Queue overflow or the report limit ends previews
   with an explicit truncation notice when delivery is still possible. A slow
   or disconnected subscriber does not block execution indefinitely: each
   notification has a one-second send bound, with one payload-free warning on
   delivery failure. The final tool result is not replaced by a progress error.
   Final preview draining shares one additional one-second bound. Unrelated
   child tokens over 128 bytes are ignored before buffering; the child request
   tokens generated by Runtime's SDK are integers.
5. No progress may outlive the request. Drain the bounded accepted preview
   tail before the final reply, stop on cancellation, and drop the receiver
   when the request ends. Progress never resets the tool's hard deadline.
   Cancellation keeps the existing current-invocation containment policy;
   previous background jobs and shared managed MCP processes are not killed.

## Internal Execution Boundary

The root Supervisor still executes no tool logic. Non-root same-binary tool
subcommands retain one input JSON and produce newline-delimited JSON on stdout:
zero or more `{"progress":{...}}` frames, then the existing single terminal
success/failure envelope. Non-Bash tools produce only the terminal frame.
The SDK never reads that private pipe directly. The Executor adapter bounds
frames and the aggregate response, rejects a missing/duplicate terminal or
progress after it, and translates previews independently of result decoding.
Child stderr remains diagnostics, never an extra progress protocol.

The execution-domain progress value does not depend on MCP types. The MCP
adapter owns token association, notification validation and delivery limits.
The managed catalog owns child token matching, not Agent/Session/ACP state.

## Verification

Tests must prove incremental delivery before completion, no-token silence,
UTF-8 boundaries, bounded flooding/slow consumers, a single terminal result,
partial output then cancellation/failure, and no cross-call token leakage.
Managed tests use the official SDK codec and a real stdio fixture; Linux
tests cover the actual non-root Executor pipe. HTTP tests use the production
stateless MCP transport rather than checking a constructed notification only.

Existing execution identity fencing, result/error envelopes, single-flight,
background-job lifetime and OTLP request spans remain regression obligations.
No progress payload, command, stdout/stderr or per-chunk span is exported to
logs/OTLP. Neither this producer nor its unit tests establish an ACP/UI
completion claim.

- Repository `make fmt-check` and `make lint` passed, including Go lint,
  all-target Rust Clippy, ACP ESLint and all frontend TypeScript checks.
- Linux Docker build: 117 unit/component tests and one non-root CLI integration
  test passed; `cargo fmt --check`, all-target Clippy with warnings denied, and
  the release build passed.
- Production-image Docker E2E: all nine scenarios passed. Real HTTP progress
  precedes controlled completion for Bash and the official SDK stdio fixture;
  failures retain a single terminal result, and cancellation reaches the exact
  child request without killing the shared MCP process or prior background jobs.
- The blocked-transport component test uses an unread 64-byte SDK transport,
  reaches the one-second delivery deadline, and preserves the execution result.
  Flood tests check queue/report bounds and truncation, including retained
  string allocation, UTF-8 boundaries and unrelated child tokens.
- Each E2E invocation owns independent signal files. Fatal-process tests permit
  an interrupted SSE body only with the required nonzero Runtime exit and fault
  log; ordinary RPC calls still require a terminal response. All suite-owned
  containers and networks are removed after completion.

No external Provider, database, browser or deployed ACP consumer was used in
this producer batch. Subsequent ACP consumer and deployment batches completed
that boundary: [F02 deployment profile](../../../scripts/acp-progress/README.md)
passed 12 Gateway ACP v1/v2 paths against actual Bash and managed stdio MCP,
including early output, cancellation, replay and Jaeger ancestry.
